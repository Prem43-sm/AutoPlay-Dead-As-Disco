DEAD AS DISCO — AI PLAYER
ZERO → COMPLETE PLAYABLE SOFTWARE ROADMAP

Project Goal
------------
Build a standalone AI game-player software that can automatically play
Dead as Disco, analyze the game screen, make decisions, control the game,
and optionally synchronize gameplay actions with the user's own music.

Final concept:
Your Music -> Music Analyzer -> AI Decision System
Game Screen -> Vision System -> Game State -> AI Decision -> Controller
Controller -> Dead as Disco -> Screen Capture -> AI loop


PHASE 0 — PROJECT DEFINITION
----------------------------
Goal:
Understand exactly what the AI needs to control.

Tasks:
- Install and analyze the game.
- Determine game resolution, FPS, controls, game mode, camera behavior,
  and keyboard/controller inputs.
- Record gameplay videos.
- Identify player, enemies, platforms, obstacles, weapons/actions,
  death screen, score, and level completion.

Deliverable:

- Controls
- Game states
- Objects
- Actions
- Win condition
- Death condition
- Camera behavior
- UI elements

PHASE 2 — SCREEN CAPTURE
------------------------

Game -> Screen -> MSS -> Frame -> OpenCV

PHASE 6 — INPUT CONTROLLER
--------------------------
Make the computer control the game.

Possible actions depending on the actual game:
- LEFT
- RIGHT
- UP
- DOWN
- JUMP
- ATTACK
- DODGE

- NONE

Create:

IMPORTANT SAFETY FEATURE:
F8 = EMERGENCY STOP

Pressing F8 must immediately release/stop all AI-controlled inputs.


PHASE 7 — FIRST NON-AI BOT
--------------------------
Do not train a neural network yet.

Build a rule-based bot.

Example logic:
- If obstacle is close -> dodge.
- If enemy is close -> attack.
- If player is falling -> jump.
- If path is clear -> move forward.

Purpose:
Prove the full pipeline:
Computer sees -> understands -> decides -> controls -> survives.

Deliverable:
A basic autonomous bot.

PHASE 11 — MUSIC-SYNCHRONIZED GAMEPLAY
--------------------------------------
Synchronize selected actions with music beats.

Pipeline:
Beat detected
  -> AI checks game state
  -> Is an action safe?
  -> Yes: synchronize action
  -> No: prioritize survival

IMPORTANT:
Game safety always has higher priority than music synchronization.

The AI should never intentionally sacrifice gameplay just to hit a beat.

PHASE 13 — REINFORCEMENT LEARNING
---------------------------------
Teach the AI to improve by experience.

Environment:
Observation -> AI -> Action -> Game -> Reward -> Learning

Example rewards:
- Survive: +1
- Enemy killed: +5
- Progress: +2
- Good dodge: +3
- Damage: -5
- Death: -20
- Level complete: +100

Possible algorithms:
- PPO
- DQN
- SAC

For a discrete action game, evaluate PPO vs DQN based on the
actual state/action design.

Goal:
The AI should learn gameplay rather than relying only on hard-coded rules.


PHASE 14 — TRAINING ENVIRONMENT
------------------------------
Create a training interface similar to a reinforcement-learning environment.

Create:
DeadAsDiscoEnv

Conceptual API:
- reset()
- step(action)
- reward()
- done()

Challenge:
Training directly against the real game can be slow.

Use recorded gameplay, controlled experiments, and optimized
environment interaction wherever practical.


PHASE 15 — HUMAN GAMEPLAY DATASET
---------------------------------
Allow the user to play normally while the software records:

- Screen
- Human action
- Game state
- Timestamp
- Music position

Create a human gameplay dataset.

Use:
Human examples
  -> Behavior cloning
  -> AI learns basic gameplay
  -> Reinforcement learning
  -> AI improves itself

This is likely more practical than starting reinforcement learning
completely from zero.


PHASE 16 — HYBRID AI

"What is happening?"

"What is likely to happen next?"

"Don't do something dangerous."

Architecture:

FIRST REAL SUCCESS TARGET
-------------------------
The most important early milestone is:

"I press START, leave the keyboard alone, and the AI successfully
plays Dead as Disco."

Once that works, everything else makes the system smarter,
more entertaining, more musical, and more autonomous.

HARDWARE NOTE
-------------
The project can be developed on a laptop with an RTX 4050 6GB.
The GPU is useful for object detection, model training, and
accelerated inference. Start with lightweight models and optimize
only after the basic playable pipeline works.

IMPORTANT DEVELOPMENT PRINCIPLE
--------------------------------
Do NOT build all phases simultaneously.

Build and verify one layer at a time:

SEE
 -> UNDERSTAND
 -> CONTROL
 -> PLAY
 -> RECORD
 -> LISTEN TO MUSIC
 -> LEARN
 -> IMPROVE
 -> UI
 -> PACKAGE

The first practical version should be a simple, reliable,
rule-based autonomous player. Machine learning and reinforcement
learning should be added after the basic game-control pipeline is
proven.
